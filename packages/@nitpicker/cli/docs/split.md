# split

`.nitpicker` アーカイブから指定したスコープ配下のページだけを抽出し、新しいアーカイブを作成します。クロールは一切行いません。

## 基本形

```sh
npx @nitpicker/cli split <archive>.nitpicker <URL> [<URL>...] -o <output>
```

例:

```sh
# -o の値は出力先の .nitpicker ファイル名（任意に指定する。ここでは分かりやすさのため
# blog-only.nitpicker とした）
npx @nitpicker/cli split site.nitpicker https://example.com/blog/ -o blog-only
npx @nitpicker/cli split site.nitpicker https://example.com/blog/ https://example.com/docs/ -o subset
```

`-o/--output` は必須です。出力先が既に存在する場合はエラーになります（上書きしません）。

`--list`/`--list-file` で作成されたアーカイブ（`roots` が URL リストであり、スコープではないもの）は split の対象にできません。

## 抽出ルール

スコープ判定は `crawl` の roots と同じ `(hostname, port, path)` 前方一致です。

| 対象                                     | ルール                                                                                                                |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `roots`                                  | 指定した URL そのもの                                                                                                 |
| スコープ内の内部ページ                   | そのまま維持（本文・メタデータ・派生データも含めて完全にコピー）                                                      |
| スコープ内リクエストのリダイレクト先     | パスがスコープ外でも内部ページとして維持（crawl 本来の挙動と同じ）                                                    |
| スコープ外だが維持ページから参照される行 | `content_items` の行のみ external stub として残す（`is_external=1`、`is_target=0`）。本文・メタデータ・派生行は落とす |
| スコープ外かつ未参照の行                 | 完全に削除（辞書テーブルの孤立行も出力に含めない）                                                                    |
| リソース（画像・CSS等）                  | 維持されるページから参照されているものだけ残す。参照がなければ落とす                                                  |

## 引き継がれるもの・引き継がれないもの

- 引き継ぐ: `--inventory`/`--recrawl` の投入済み URL リスト、テンプレートの名前（再分類時の名前の継承元になる）
- ページのテンプレート分類は抽出後のページで再実行されます（元のクラスタは元アーカイブ全体で計算されたもので、抽出後の構成とは一致しないため）。`--skip-templates` でスキップできます
- viewer read model は常に無条件で再構築されます

## 後続の作業

- 指定したスコープが元のアーカイブの roots より広い場合、元では未取得の外部リンクとして記録されていたページが新スコープ内に入ることがあります。取得したい場合: `npx @nitpicker/cli crawl <out> --append <root>`
- テンプレート分類または read model の再構築に失敗した場合: `npx @nitpicker/cli viewer-build <out>`

## オプション一覧

| オプション         | 型            | 説明                                                               |
| ------------------ | ------------- | ------------------------------------------------------------------ |
| `-o, --output`     | string (必須) | 出力 `.nitpicker` パス。`.nitpicker` 拡張子は省略可                |
| `--skip-templates` | boolean       | 出力アーカイブでのテンプレート再分類をスキップ                     |
| `--verbose`        | boolean       | 各進捗行に ISO 8601 タイムスタンプを付けて追記出力（上書きしない） |

## 終了コード

| コード | 意味                                                                                                |
| ------ | --------------------------------------------------------------------------------------------------- |
| `0`    | 成功                                                                                                |
| `1`    | 引数検証エラー（`--list` アーカイブの指定、スコープに何も一致しない等）、または処理中の致命的エラー |
| `2`    | 書き込みは完了したが、pending が非空、またはテンプレート分類・read model 再構築が失敗               |
